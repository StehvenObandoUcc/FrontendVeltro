Problemas software y posibles soluciones que debes evaluar si estan en lo correcto o no: 
## 1. 📂 Módulo de Autenticación y Usuarios

**Fallo detectado:** Inexistencia de registro/login funcional (imposibilidad de crear nuevos usuarios).

**Causa Raíz:** 
Según la arquitectura documentada (módulo IAM), el backend solo expone `/api/v1/auth/login`, `/refresh` y `/logout`. Falta contexto en los archivos de código proporcionados (clases `.java` del `AuthController`) para confirmar si el endpoint de registro fue omitido intencionalmente. Además, el `DevDataInitializer` inyecta un usuario admin directamente en la base de datos (H2/PostgreSQL), lo que confirma que el flujo de creación pública no está desarrollado en el servicio.

**Plan de Acción:**
1. **Backend:** Crear el endpoint `POST /api/v1/auth/register` en `AuthController`.
2. **Backend:** Implementar el método en `AuthService` que reciba el DTO (email, password, nombre), encripte la contraseña usando `PasswordEncoder` y asigne un rol por defecto (`CASHIER` o `WAREHOUSE`).
3. **Frontend:** Añadir el componente `RegisterPage.tsx` con su respectivo formulario (React Hook Form + Zod) y conectarlo al `authStore` de Zustand para manejar el estado global de la sesión al completar el registro.

## 2. 📊 Dashboard y Reportes (Exportación)

**Fallo detectado:** Error en exportación PDF/Excel y visualización de productos sin stock en el dashboard.

**Causa Raíz:** 
Para la exportación, falta contexto en los archivos de código proporcionados para ver cómo Axios maneja la respuesta del endpoint `/api/v1/reports/export`. Frecuentemente, este error ocurre porque el frontend no define el `responseType: 'blob'` en la petición, corrompiendo el archivo generado. Para el problema del stock, los endpoints del `Dashboard` no están cruzando correctamente los datos con el `AlertService` o la consulta SQL nativa no está trayendo los productos en estado `OUT_OF_STOCK`.

**Plan de Acción:**
1. Verificar que la petición Axios en `ExportButtons.tsx` incluya `responseType: 'blob'`.
2. Utilizar `URL.createObjectURL(blob)` para forzar la descarga en el navegador.
3. Revisar el query del endpoint del Dashboard para asegurar que consuma el estado actualizado de `InventoryMovement` y no un caché obsoleto.

## 3. 🛒 Punto de Venta (POS) y Hardware

**Fallo detectado:** Error `BrowserMultiFormatReader.listVideoInputDevices is not a function` y problemas de renderizado en pantallas divididas.

**Análisis Técnico:**
1. **Error de Scanner:** El error ocurre porque el método `listVideoInputDevices` fue deprecado o removido en las versiones recientes de `@zxing/library`. Alternativamente, puede estar fallando por un problema de contexto de seguridad: la API `navigator.mediaDevices.getUserMedia` (utilizada por debajo por ZXing) **solo funciona en contextos seguros (HTTPS o localhost)**. Si se accede desde una IP de red (ej. `http://192.168.1.5`), el navegador bloquea la función de video. Se debe actualizar la importación a `@zxing/browser` o asegurar la ejecución bajo HTTPS.
2. **Pantalla Dividida:** El fallo responsive en POS se debe a flexbox forzados (`flex-row`). Cambiar los selectores del contenedor principal a `flex flex-col md:flex-row` para asegurar que el carrito y el catálogo se apilen verticalmente en ventanas estrechas.

## 4. 📦 Gestión de Inventario y Productos (El Corazón del Sistema)

**Fallo detectado:** Falta campo 'Stock', error "Categoría Padre", alertas incompletas y fase 2 vacía.

**Replanteamiento (Categorías y Alertas):**
* **Categorías:** Pensamiento sistémico: **No se debe eliminar la "Categoría Padre" directamente de la base de datos** sin antes migrar los datos. En una estructura relacional (PostgreSQL/H2), la columna `parent_id` suele ser una llave foránea auto-referenciada. Borrarla romperá la integridad referencial y las migraciones Flyway fallarán. *Solución:* Ocultar la selección de categoría padre en el frontend (UI plano) y enviar el ID de categoría raíz por defecto en el payload. Para la creación, integrar el modal de "Nueva Categoría" directamente en el formulario de `ProductFormPage`.
* **Alertas:** Se deben agregar 3 campos numéricos a la entidad `Product` y a su formulario frontend: `minStockInfo`, `minStockWarning`, `minStockCritical`. El `AlertService` del backend usará el patrón Chain of Responsibility para comparar el `Stock` actual contra estos intervalos e inyectar el estado correcto en el Dashboard.

**Integración IA e Inventario (Flujo sin Código de Barras):**
1. **Captura:** Activar un modal en el POS/Productos usando la cámara para tomar una foto del artículo.
2. **Procesamiento:** Enviar la imagen en Base64 al endpoint `/api/v1/scanner/ai-scan` (B3-01 Vision API).
3. **Mapeo:** El backend devuelve un JSON con: `nombre_sugerido`, `categoria_inferida`, `precio_estimado`.
4. **Inventario:** Como no hay código de barras físico, el backend generará automáticamente un SKU interno (ej. `SKU-AI-8492`).
5. **Flujo de Stock:** Al registrar el producto, se le asigna un inventario inicial de entrada. Durante la venta en el POS, el cajero busca el producto por nombre o SKU generado, y al procesar el pago, el sistema de eventos (`InventoryMovement`) descuenta el stock basándose en ese identificador único garantizando trazabilidad.

## 5. 🚚 Órdenes de Compra y Proveedores

**Fallo detectado:** Bloqueo en creación de 'Suppliers' y falta de metadatos (fechas/comprobantes).

**Causa Raíz:** 
El bloqueo en la creación del proveedor ocurre generalmente por una desincronización entre el esquema de validación frontend (Zod) y la entidad Backend. Falta contexto en los archivos de código proporcionados para leer la validación exacta, pero si el formulario exige un dato que el backend rechaza, la petición fallará silenciosamente. La falta de fechas y recibos se debe a que la entidad `PurchaseOrder` actual (fase 2) no contempla columnas para metadatos avanzados.

**Plan de Acción:**
1. Modificar la entidad `PurchaseOrder` (y crear una nueva migración Flyway) para incluir: `expectedDeliveryDate` (Timestamp), `receiptImage` (String/URL), y `status` (Enum: PENDING, DUE, RECEIVED).
2. Añadir un campo de tipo `<input type="file" />` en React, convertir la imagen a Base64 y enviarla en el payload al crear la orden.
3. Revisar las reglas Zod en el formulario `Supplier` para asegurar que hagan match con el DTO del backend.

## 6. 🎨 Ajustes de Layout (UI/UX)

**Fallo detectado:** Pantalla en negro al reducir el tamaño, menú desaparecido y contenedores de categorías achicados.

**Acción:** 
Revisar las siguientes clases Tailwind en el frontend:
1. **Sidebar/Panel de Control:** Quitar las clases que oculten el menú abruptamente (como `hidden md:block` sin un menú de hamburguesa de respaldo). Si la pantalla queda en negro, es probable que haya una capa de overlay (`bg-black/50`) cuyo `z-index` esté pisando el contenido principal.
2. **Contenedor Principal (MainLayout):** Cambiar `h-screen overflow-hidden` por `min-h-screen flex flex-col`. Esto permite que el contenido crezca en móvil en lugar de cortarse.
3. **Categorías:** El contenedor de las categorías debe tener `w-full flex-wrap` o un `grid grid-cols-2 md:grid-cols-4` para que las tarjetas de categorías se adapten y ocupen el ancho total de la pantalla en lugar de encogerse perdiendo legibilidad.
